什么是小程序 —— 定义与特点
1.1 小程序的定义与特点

小程序的定义

小程序是一种无需下载安装即可使用的应用，它通常依托于某个平台级应用运行。

📥

无需下载安装

依托平台运行，不占用手机存储

👆

触手可及

扫一扫或搜一搜即可打开应用

🚶

用完即走

生命周期短、轻量化，无需卸载

🔧

开发门槛低

开发难度不及 App，可持续迭代

💭 课堂互动

结合日常应用场景，让学生思考小程序的其他特点

AI 在小程序中的典型应用场景
6.2 智能客服
💬
智能客服

自动回复 · 意图识别 · 多轮对话

通过自然语言处理技术，让小程序具备自动理解用户问题并给出精准回复的能力，实现 7×24 小时在线服务。

📌 具体应用案例

  • 电商小程序：用户咨询"这件衣服有M码吗？"AI 自动识别意图，查询库存后回复并推送购买链接
  • 银行小程序：用户输入"查询本月账单"，AI 理解语义后自动调取数据并展示账单摘要
  • 酒店预订小程序：用户说"帮我改签到周五"，AI 完成多轮对话确认信息后自动办理改签

6.2 语音交互
🎤
语音交互

语音输入 · 语音搜索 · 语音播报

将语音识别与合成技术融入小程序，让用户通过语音完成输入、搜索和获取反馈，提升操作效率与无障碍体验。

📌 具体应用案例

  • 点餐小程序：用户对着手机说"我要一份宫保鸡丁套餐"，系统自动识别并加入购物车
  • 音乐小程序：用户语音搜索"播放周杰伦的晴天"，直接跳转播放
  • 导航小程序：行程中自动语音播报"前方200米右转"，无需看屏幕

图像识别

6.2 智能表单
📝
智能表单

自动填充 · 智能校验 · 内容生成辅助

利用 AI 技术简化表单填写流程，自动识别用户信息并完成校验，同时辅助生成规范内容，大幅提升填单效率。

📌 具体应用案例

  • 订单小程序：AI 自动校验地址格式与邮编匹配，并提示修正错误

6.2 智能搜索
🔍
智能搜索

语义理解 · 精准匹配

基于自然语言处理与向量检索技术，让小程序能够理解用户搜索意图，返回最相关的结果，而非简单关键词匹配。

📌 具体应用案例

  • 知识库小程序：用户搜索"怎么办理护照"，AI 理解意图后直接展示办理流程与材料清单
  • 商品搜索：用户输入"适合送礼的茶叶"，AI 精准匹配礼品茶并排序推荐
  • 法律咨询小程序：用户描述"劳动仲裁流程"，AI 定位相关法条与操作指引

什么是 JSON

JSON（JavaScript Object Notation，JS 对象简谱）是一种轻量级的数据交换格式，层次结构清晰简洁。

用大括号 { } 包起来，里面的每一条信息都是一个"键值对"（键 : 值），中间用冒号 : 分开，不同信息用逗号 , 隔开。

例 1：包裹信息

{ "寄件人": "张三", "电话": "66666666666", "收件人": "李四", "收件地址": "上海市杨浦区xxx路xx号", "物品": "书" }

取值：包裹信息.电话 → "66666666666"；取"物品"呢？

JSON 介绍
嵌套结构与数组

例 2：嵌套的包裹信息

值可以是对象 { }（再嵌套键值对），也可以是数组 [ ]（如 "物品" 的值是一列物品）。

{ "人员信息": { "寄件人": "张三", "收件人": "李四" }, "电话": { "收件电话": "66666666666", "寄件电话": "88888888888" }, "地址": { "收件地址": "上海市杨浦区xxx路xx号", "寄件地址": "北京市XX区XX路XX号" }, "物品": ["杯子", "易碎物品"], "重量": "3kg" }

什么是 Flex

Flex 是 Flexible Box 的缩写，意为"弹性布局"，为盒状模型提供最大的灵活性。用于布局时，容器开启 display: flex，其子元素自动成为 Flex 项目。

容器 vs 项目

容器 (container)：启用 Flex 布局的元素
项目 (item)：容器的直接子元素

.container { display: flex; }

图片格式怎么选
JPG · PNG · SVG · WEBP

image 组件支持的图片格式

image 组件支持 JPG、PNG、SVG、WEBP、GIF 等主流图片格式，选对格式直接影响体积、清晰度、兼容性。

格式特点适用场景
JPG 有损压缩、压缩率高、不支持透明 普通照片、banner 大图
PNG 无损、支持透明、兼容性好 需要透明背景的图标、UI
SVG 矢量图、代码内嵌、体积小 图标、logo、样式简单的图
WEBP 压缩程度好、iOS webview 有兼容问题 面向安卓的优化场景
GIF 支持动画、体积较大 加载动效、短动画
📌 项目实践：icon 用 SVG/PNG，大图用 JPG，控制总包体积（小程序首包 ≤ 2MB）。

幻觉问题与模型局限性
大模型不完美 · 理性使用

⚠️ 幻觉 (Hallucination)

什么是幻觉？
编造看似真实的事实或引用，内容往往错误但表现得非常自信。
产生原因
优化目标是预测概率而非事实准确性；缺乏真实世界的知识和验证能力，无法判断真伪。

⚠️ 核心局限性

缺乏真正的理解与意识
本质上是基于统计模式的匹配，而非真正的认知理解。
潜在的数据偏见
训练数据中存在的偏见可能被模型放大，导致输出结果存在偏差。

逻辑交互
数据绑定 + 事件绑定 = 双闭环
📥

数据绑定（视图 ← 数据）

用 {{data}} 把 JS 中的变量渲染到 WXML 里；数据一变，视图自动更新。

<view>{{count}}</view>
📤

事件绑定（事件 → 逻辑）

用 bindxxx 把组件事件绑定到 JS 函数；用户操作时，函数被调用。

<button bindtap="onAdd">＋</button>

双向闭环

事件修改 data → 视图更新（数据绑定）；视图展示 data → 用户看到变化（数据绑定）。两者配合构成完整的交互闭环。

4
输入事件
bindinput · bindlinechange

输入事件

在用户输入过程中（每键入一个字符）持续触发，适合实时校验、字数统计、联想搜索。

<input bindinput="onInput" placeholder="请输入姓名" value=="{{name}}" /> <textarea bindlinechange="onLineChange" placeholder="留言（回车换行）" /> // JS onInput(e) { this.setData({ name: e.detail.value }) } onLineChange(e) { // 每换行一次触发一次 console.log(e.detail.value) }
⚠️ 注意：bindinput 触发频率高，避免在其中做重计算或网络请求。
5
改变事件
bindchange · bindblur

改变事件

在选择类组件值确定改变后触发；比输入事件更"稳"，常用于提交前的最终校验。

bindchange

值改变完成时触发

<switch bindchange="onSwitch"/> <picker bindchange="onPick"/>

bindblur

输入框失去焦点时触发

<input bindblur="onBlur" bindinput="onInput" />
6
点击事件
bindtap —— 最基础也最常用

用法

在组件属性上添加 bindtap，赋一个函数名。当点击该组件时，触发对应的函数执行。

<button bindtap="addCart">加入购物车</button> <text bindtap="onTapText">点击我</text> <view bindtap="onTapView">点我</view> // JS addCart(e) { // e.currentTarget.dataset 拿到 data-xxx console.log('点击了按钮') }
💡 支持的组件：button / text / view / image / navigator 等大多数组件。
7
事件冒泡与 catchtap
嵌套标签的事件传递

什么是事件冒泡？

多层标签嵌套时使用 bindtap 绑定事件，里层事件发生后，外层会相应触发（点击事件向外层传递）。

🌊 bindtap → 冒泡

点击内层，内层+外层函数都执行

<view bindtap="outer"> <text bindtap="inner"> 内层 </text> </view> // 结果：inner → outer

🛑 catchtap → 阻止冒泡

点击内层，仅内层函数执行

<view bindtap="outer"> <text catchtap="inner"> 内层 </text> </view> // 结果：仅 inner
